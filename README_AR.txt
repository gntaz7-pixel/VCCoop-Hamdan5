Bully Co-op Hamdan v0.16a — تجربة اتصال محلي معزولة (كود المصدر)

الهدف: جهاز واحد، نافذتان للعبة Bully، Host وGuest. جيمي الثاني مجرد NPC تابع لإحداثيات اللاعب بالنسخة الثانية، وليس Co-op كامل.

ما تغير:
- إصدار بروتوكول UDP رقم 2: يمنع ملفات FAKE_GUEST القديمة وإصدار DLL السابق من الاتصال.
- إضافة NET CONFIG في اللوق: دور النسخة، المنفذ، رمز الجلسة، نسخة البروتوكول، ومسار ملف INI المقروء.
- إضافة PEER VERIFIED في اللوق: يثبت استقبال حزمة من الطرف المقابل ويكتب عنوانه ومنفذه.
- إضافة RX IGNORED: عدد الحزم القديمة / الرموز المختلفة / الحزم الأخرى.
- بيانات التشخيص لا تغير حركة جيمي ولا تلغي حماية الشخصية الثانية.

التركيب:
1. احفظ ملفاتك وسيفاتك. أغلق لعبتي Bully وأي نافذة FAKE_GUEST PowerShell قديمة.
2. فك ZIP وارفع جميع ملفات المصدر إلى GitHub.
3. GitHub Actions > Build Bully Co-op ISOLATED LOOPBACK v0.16a (x86).
4. نزل dinput8.dll الجديد وضع نفس النسخة في مجلدي Bully_HOST وBully_GUEST.
5. انسخ HOST_COPY/BullyCoop.ini بجانب Bully.exe في مجلد HOST.
6. انسخ GUEST_COPY/BullyCoop.ini بجانب Bully.exe في مجلد GUEST.
7. افتح اللعبتين بشكل مستقل وحمّل لعبتك في نفس منطقة مفتوحة ومستوية.
8. قبل الضغط على F9 أو F10، افتح اللوقين وتأكد من ظهور:
   NET CONFIG ... role=host port=7792 code=593741 ... protocol=2
   NET CONFIG ... role=guest port=7792 code=593741 ... protocol=2
   PEER VERIFIED role=guest   داخل لوق HOST
   PEER VERIFIED role=host    داخل لوق GUEST
9. إذا لم تظهر PEER VERIFIED في الملفين، أوقف التجربة وارسل الملفين لتحديد المشكلة.
10. فقط بعد نجاح الاتصال اضغط F9 ثم F10 في HOST مرة واحدة، وانتقل لـGUEST وامشِ مسافة 10 أمتار في منطقة مفتوحة. أعد HOST للأمام للمشاهدة.
11. اضغط F10 على HOST لإيقاف الأوامر الجديدة. لا تحفظ اللعبة أثناء الاختبار.

مهم: ظهور PEER VERIFIED يثبت استقبال بيانات الشبكة فقط، وليس نجاح المشي.
WALK UNSAFE ممكن يوقف حركة NPC إذا اقترب كثيرًا من جيمي المضيف.
ممكن اللعبة توقف محاكاة الفيزياء وهي بالخلفية حتى لو المود يسمح بأوامر المشي.
المود غير مختبر داخل ويندوز بعد؛ الكود يبنى على GitHub Actions MSVC x86.
التجربة محلية فقط (127.0.0.1) ولا يوجد لعب أونلاين كامل بعد.
