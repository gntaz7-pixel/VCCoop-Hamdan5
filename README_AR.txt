Bully Co-op Hamdan Edition — v0.3 — اختبار دخول إلى اللعبة (وليس مود لعب جماعي)
========================================================================

ما الذي يفعل هذا الاختبار؟
- يقدّم dinput8.dll وسيطاً يستخدم DINPUT8.dll الأصلي من مجلد نظام ويندوز.
- إذا استدعته لعبة Bully، يكتب BullyCoop_bridge.log بجانب Bully.exe.
- لا يضيف لاعبين، ولا يرسل بيانات عبر الشبكة، ولا يغيّر ذاكرة اللعبة أو الحفظ.

نسخة اللعبة التي فُحصت (من الملف الذي أرسله حمدان):
Bully: Scholarship Edition — Windows PE32 x86
الحجم: 8,204,288 bytes
SHA-256: bd6e757dba71f04539f0c3a66dd216f40450456f0012becd2e14848dd3ec174e
ملاحظة: هذه بصمة دقيقة للملف المرفوع، وليست إثباتاً لرقم إصدار اللعبة.

طريقة البناء بدون تثبيت Visual Studio:
1. أنشئ مستودع GitHub جديداً مثلاً BullyCoop-Hamdan (لا تستخدم مستودع Vice City).
2. ارفع محتويات هذا المجلد إلى جذر المستودع، لا مجلد إضافي.
3. تأكد أن .github/workflows/build-bully-bridge.yml موجود داخل جذر المستودع.
4. افتح GitHub Actions > Build Bully Co-op Bridge Probe (x86) > Run workflow.
5. إذا نجح، حمّل Artifact باسم BullyCoop-Hamdan-Bridge-Probe-x86.
6. فك الضغط وستجد dinput8.dll.

التجربة داخل اللعبة:
1. استخدم نسخة احتياطية مستقلة من Bully Scholarship Edition.
2. أغلق اللعبة وخذ نسخة احتياطية من أي dinput8.dll موجود بجانب Bully.exe.
   لا تحذف ملفات المودات الأخرى؛ هذا النوع من ملفات DLL يتعارض مع وسطاء أخرى بنفس الاسم.
3. ضع dinput8.dll الجديد بجانب Bully.exe، وشغّل Bully.exe كالمعتاد.
4. تأكد من ظهور BullyCoop_bridge.log بجانب Bully.exe، وابحث عن:
   BullyCoop probe: DirectInput8Create forwarded successfully
5. إذا اللعبة ما اشتغلت، احذف ملف dinput8.dll الجديد ورجّع القديم.
6. إذا ما ظهر السجل، تأكد من صلاحيات الكتابة إلى مجلد اللعبة، أو أرسل تفاصيل النسخة.

هذي أول مرحلة ربط فعلية: التأكد أن لعبتك تحمل DLL خاصاً بنا بلا تعطيل الإدخال.
المرحلة التالية ستكون تحديد بيانات إحداثيات اللاعب وربطها بتجربة الشبكة v0.2.

تعني نجاحه داخل اللعبة. تجنب رفع ملف Bully.exe نفسه إلى GitHub.
